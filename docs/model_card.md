# FactoryMind Model Card

Team Sodium | International AI Builders Congress (hackathon MVP)

## Model details

- **Model:** scikit-learn `RandomForestClassifier`
- **Hyperparameters:** `n_estimators=400`, `min_samples_leaf=2`,
  `max_features="sqrt"`, `class_weight="balanced_subsample"`,
  `random_state=42`, `n_jobs=-1`
- **Preprocessing:** median imputation (numeric), most-frequent imputation +
  one-hot encoding (`Type`), inside a single `Pipeline`/`ColumnTransformer`
- **Features (input, exactly six):** `Type`, `Air temperature [K]`,
  `Process temperature [K]`, `Rotational speed [rpm]`, `Torque [Nm]`,
  `Tool wear [min]`
- **Target:** `Machine failure` (0/1)
- **Excluded by design (leakage):** `TWF`, `HDF`, `PWF`, `OSF`, `RNF`
  (failure-mode labels), `UDI`, `Product ID` (identifiers)
- **Trained:** 2026-11-20, scikit-learn 1.5.2, Python 3.12
- **Artifact:** `models/factorymind_model.joblib` (+ `models/metrics.json`)

## Intended use

- Decision support for maintenance planning on rotating machinery similar to
  the AI4I 2020 setting (milling/spindle-style process with tool wear).
- Risk **triage and ranking**: which machines deserve inspection first.
- Human-in-the-loop: every output is advisory; a qualified engineer approves
  any action. FactoryMind is not an autonomous control system.

## Out-of-scope use

- Real-time safety-critical control or automatic shutdown.
- Equipment whose failure physics differs substantially from the dataset's
  documented mechanisms without re-validation.
- Any use treating the score as a calibrated probability of failure.

## Training data

UCI AI4I 2020 Predictive Maintenance Dataset (CC BY 4.0, DOI 10.24432/C5HS5C),
10,000 rows, 3.39% failure rate. **The dataset is synthetic** - generated by
the dataset authors to emulate failure mechanisms (tool wear, heat
dissipation, power, overstrain, random failures). See
`docs/data_provenance.md`.

## Splits (stratified, seed 42)

| Split | Rows | Failures | Failure rate | Used for |
|---|---|---|---|---|
| Train | 6,000 | 203 | 3.38% | fitting the pipeline |
| Validation | 2,000 | 68 | 3.40% | threshold + tier derivation |
| Test | 2,000 | 68 | 3.40% | reporting only (used once) |

## Evaluation (held-out test split, alert threshold 0.31)

| Metric | Value |
|---|---|
| ROC-AUC | 0.976 |
| PR-AUC (average precision) | 0.709 (chance level 0.034) |
| Precision | 0.613 |
| Recall | 0.721 |
| F1-score | 0.662 |
| Accuracy | 0.975 |
| Balanced accuracy | 0.852 |

Confusion matrix (rows = actual, columns = predicted):

|  | Predicted OK | Predicted failure |
|---|---|---|
| **Actual OK** | 1,901 | 31 |
| **Actual failure** | 19 | 49 |

Interpretation: at the alert operating point the model catches 72% of
failures with 61% precision - roughly one in three alerts is a false alarm,
and about 28% of failures are missed. These trade-offs are visible on the
ROC/PR curves in the app (Model Performance page).

## Operating thresholds (validation-derived)

| Threshold | Value | Derivation |
|---|---|---|
| Alert (decision) | 0.31 | F1-maximising cut-off on validation |
| Medium tier | 0.024 | 80th percentile of validation scores |
| High tier | 0.244 | 95th percentile of validation scores |

## Feature importance (permutation, test split, 8 repeats)

| Feature | Mean decrease in log-loss |
|---|---|
| Tool wear [min] | 0.098 |
| Torque [Nm] | 0.070 |
| Rotational speed [rpm] | 0.036 |
| Air temperature [K] | 0.035 |
| Process temperature [K] | 0.011 |
| Type | 0.002 |

Tool wear and the torque/speed pair dominate - consistent with the dataset's
documented failure mechanisms. Rotational speed and torque are strongly
anti-correlated in the data; their importance is shared.

## Explanations

- **Global:** permutation importance (mean decrease in log-loss, 8 repeats on
  the test split).
- **Local (per prediction):** one-at-a-time sensitivity - each feature is set
  to its typical healthy training value while the rest are held fixed; the
  change in predicted risk is reported. This describes model behaviour, not
  physical causation.

## Limitations and cautions

1. **Synthetic data.** All metrics quantify behaviour on the AI4I 2020
   synthetic distribution. They are not evidence of performance on real
   factory telemetry.
2. **Not calibrated.** Scores are Random Forest vote shares; no calibration
   (Platt/isotonic) was implemented or evaluated.
3. **Class imbalance.** 3.4% positive rate; precision at the alert threshold
   (0.61) means false positives are expected - by design, since missed
   failures are costlier.
4. **Threshold transfer.** Thresholds are derived from the same synthetic
   distribution; re-derive them on target-domain validation data before
   production use.
5. **Correlated features.** Speed/torque share credit; OCAT explanations
   cannot capture interaction effects.
6. **Small positive counts.** 68 test positives; metrics carry non-trivial
   sampling uncertainty (single split reported).
